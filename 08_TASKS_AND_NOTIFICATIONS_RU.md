**Назначение:** описать систему внутренних задач, уведомлений, приоритетов, триггеров, адресатов, условий закрытия и отображения в UI для v1  

---

## 1. Назначение документа

Этот документ описывает систему задач и уведомлений в первой версии продукта **My School** для школы **Азбука движения**.

В v1 уведомления реализуются как **внутренние задачи в системе**.

Документ нужен для:

- проектирования backend-логики задач;
- проектирования UI операционного центра;
- проектирования UI центра задач;
- постановки задач Codex;
- описания cron/scheduler-процессов;
- проверки бизнес-правил;
- написания acceptance criteria;
- ручного и автоматического тестирования.

---

## 2. Главный принцип

В v1 нет внешних уведомлений.

Не реализовывать:

```text
Telegram-уведомления
VK-уведомления
SMS
Email
Push
Родительские уведомления
```

Вместо этого все уведомления создаются как внутренние задачи:

```text
Task
```

Задача должна быть видна пользователю в интерфейсе до тех пор, пока она не закрыта.

---

## 3. Что такое Task

`Task` — это внутренняя задача/уведомление, которая сообщает пользователю, что нужно выполнить конкретное действие.

Примеры:

```text
Табель не заполнен до 18:00.
Ребёнок взял занятие в долг.
Ребёнок не допущен к занятию.
Ожидается справка.
Нужно проверить болезнь через неделю.
Нужно назначить перенос.
Группа больше 15 детей.
Пробника нужно обработать после занятия.
```

Task должна иметь:

- тип;
- приоритет;
- адресата;
- статус;
- связанную сущность;
- заголовок;
- описание;
- дату создания;
- дедлайн, если применимо;
- дату закрытия;
- пользователя, который закрыл задачу.

---

## 4. Роли и задачи

## 4.1 SUPER_ADMIN

SUPER_ADMIN может:

- видеть все задачи;
- закрывать все задачи;
- создавать ручные задачи;
- фильтровать задачи;
- видеть критичные задачи;
- видеть задачи админов и тренеров.

## 4.2 ADMIN

ADMIN может:

- видеть свои задачи;
- видеть все операционные задачи;
- видеть задачи тренеров;
- закрывать задачи;
- создавать ручные задачи;
- обрабатывать задачи по детям, группам, расписанию, справкам, переносам, оплатам и пробникам.

## 4.3 COACH

COACH может:

- видеть только задачи, назначенные ему;
- видеть задачи, связанные с его занятиями;
- закрывать свои задачи, если действие выполнено;
- открывать связанное занятие из задачи.

COACH не может:

- видеть все задачи школы;
- видеть задачи других тренеров;
- видеть финансовые детали задачи;
- закрывать административные задачи;
- менять приоритеты задач.

---

## 5. Статусы задач

```text
OPEN
IN_PROGRESS
CLOSED
CANCELLED
```

## 5.1 OPEN

Задача создана и ожидает действия.

## 5.2 IN_PROGRESS

Пользователь взял задачу в работу.

В v1 этот статус можно реализовать опционально. Минимально достаточно `OPEN` и `CLOSED`.

## 5.3 CLOSED

Задача выполнена и закрыта.

## 5.4 CANCELLED

Задача отменена, потому что больше не актуальна.

Например:

- задача по справке отменена, потому что отсутствие финализировано другим способом;
- задача по долгу отменена после корректировки;
- задача по пробнику отменена, если пробник удалён/закрыт.

---

## 6. Приоритеты задач

```text
CRITICAL
HIGH
MEDIUM
LOW
```

## 6.1 CRITICAL

Используется, если задача влияет на:

- занятие сегодня;
- допуск ребёнка;
- деньги/долг;
- операционную блокировку;
- невозможность провести занятие корректно.

Примеры:

```text
Табель не заполнен до 18:00.
Ребёнок взял занятие в долг.
Ребёнок не допущен.
Тренер не назначен на занятие.
Ребёнок пришёл без активного абонемента.
Превышен допустимый долг.
```

## 6.2 HIGH

Используется, если нерешённая задача может привести к ошибке в:

- переносах;
- списаниях;
- справках;
- обработке пробников;
- перегрузе группы;
- операционном контроле.

Примеры:

```text
Ожидается справка.
Проверить болезнь через неделю.
Нужно назначить перенос.
Пробник требует обработки.
Группа больше 15 детей.
Есть отсутствие без финальной причины.
```

## 6.3 MEDIUM

Используется для важных, но не срочных операционных задач.

Примеры:

```text
Проверить расписание следующего месяца.
Подготовить статусы оплаты.
Проверить заполненность группы.
Обновить данные ребёнка.
Проверить медицинские ограничения.
```

## 6.4 LOW

Используется для информационных или вспомогательных задач.

Примеры:

```text
Заполнить необязательные поля пробника.
Обновить заметки по инвентарю.
Уточнить комментарий.
Проверить старую запись.
```

---

## 7. Каналы уведомлений v1

В v1 используется только один канал:

```text
IN_APP_TASK
```

Это означает:

- задача отображается в системе;
- задача видна в операционном центре;
- задача видна в центре задач;
- задача видна тренеру в разделе “Мои задачи”, если назначена ему.

Не использовать:

```text
Telegram
VK
SMS
Email
Push
```

---

## 8. Где отображаются задачи

## 8.1 Операционный центр админа

Показывает:

- CRITICAL задачи;
- HIGH задачи;
- задачи, требующие действия сегодня;
- задачи по неотмеченным занятиям;
- задачи по долгам;
- задачи по недопуску;
- задачи по справкам;
- задачи по переносам;
- задачи по пробникам;
- задачи по перегруженным группам.

## 8.2 Центр задач админа

Показывает все задачи, доступные админу.

Фильтры:

- приоритет;
- статус;
- тип;
- адресат;
- дата;
- связанная сущность.

## 8.3 Интерфейс тренера

Показывает только задачи тренера:

- не заполнен табель;
- назначена замена;
- ребёнок взял занятие в долг;
- ребёнок не допущен;
- в занятии есть пробник.

## 8.4 Карточки сущностей

Задачи также могут отображаться в связанных сущностях:

- карточка ребёнка;
- карточка группы;
- занятие;
- карточка пробника;
- борд болезней;
- борд переносов.

Кому назначена задача.

- конкретному админу;
- системному admin queue;

Для v1 рекомендуется простая модель:

```text

Тренерские задачи назначаются конкретному COACH.
```

# 11. ATTENDANCE_NOT_FILLED

## 11.1 Назначение

Задача создаётся, если тренер не заполнил табель посещаемости до 18:00 в день занятия.

## 11.2 Триггер

```text
Каждый день в 18:00 система проверяет занятия текущего дня.
Если Lesson.status != ATTENDANCE_COMPLETED, создать задачу.
```

## 11.3 Получатели

Создать две задачи или одну задачу с двумя адресатами:

```text
COACH занятия
ADMIN
```

Рекомендуется создавать отдельные задачи:

```text
1 задача тренеру
1 задача админу
```

## 11.4 Приоритет

```text
CRITICAL
```

## 11.5 Связанная сущность

```text
Lesson
```

## 11.6 Заголовок

```text
Табель не заполнен
```

## 11.7 Описание

```text
Посещаемость по занятию {group_name} от {lesson_date} {start_time} не заполнена до 18:00.
```

## 11.8 Условие закрытия

Задача закрывается, когда:

```text
Lesson.status = ATTENDANCE_COMPLETED
```

или когда ADMIN вручную закрывает задачу с комментарием.

## 11.9 Важное правило

Система не должна автоматически списывать занятия, если табель не заполнен.

# 12. CHILD_TOOK_CREDIT_LESSON

## 12.1 Назначение

Задача создаётся, когда ребёнок использовал одно занятие в долг.

## 12.2 Триггер

```text
Баланс ребёнка был 0.
Ребёнок отмечен PRESENT.
Система списала занятие.
Баланс стал -1.
```

## 12.3 Получатели

```text
ADMIN
```

Также тренер должен видеть статус у ребёнка:

```text
CREDIT_LESSON_USED
```

## 12.4 Приоритет

```text
CRITICAL
```

## 12.5 Связанная сущность

```text
Child
Subscription
Lesson
```

Основная связанная сущность:

```text
Child
```

## 12.6 Заголовок

```text
Ребёнок взял занятие в долг
```

## 12.7 Описание

```text
{child_name} посетил занятие в долг. Необходимо проконтролировать оплату до следующего занятия.
```

## 12.8 Условие закрытия

Задача закрывается, когда:

- админ обновил статус оплаты;
- создан/обновлён абонемент;
- баланс восстановлен;
- admission_status больше не `CREDIT_LESSON_USED` или `NOT_ADMITTED`.

## 12.9 UI для тренера

Тренеру показывать не задачу о деньгах, а простой статус:

```text
Взял 1 занятие в долг
```

```text
Баланс = -1.

```

## 13.3 Получатели

```text
ADMIN
COACH занятия
```

Рекомендуется:

- админу создать задачу;
- тренеру показать предупреждение на экране занятия.

## 13.4 Приоритет

```text
CRITICAL
```

## 13.5 Связанная сущность

```text
Child
Lesson
```

## 13.6 Заголовок

```text
Ребёнок не допущен к занятию
```

## 13.7 Описание для админа

```text
{child_name} не допущен к занятию из-за неоплаченного долга. Проверьте оплату или абонемент.
```

```text
{child_name} не допущен к занятию. Обратитесь к администратору.
```

Задача закрывается, когда:

COACH не может обойти `NOT_ADMITTED`.

# 14. SICKNESS_FOLLOW_UP

## 14.1 Назначение

Напомнить админу проверить статус болезни ребёнка.

## 14.2 Триггер

```text
Через 7 дней после установки ABSENT_SICK_PENDING.
```

Пользователь ранее указал:

```text
Напоминание через неделю после определения статуса отсутствия из-за болезни.
```

## 14.3 Получатели

```text
ADMIN
```

## 14.4 Приоритет

```text
HIGH
```

## 14.5 Связанная сущность

```text
AttendanceRecord
Child
```

## 14.6 Заголовок

```text
Проверить статус болезни
```

## 14.7 Описание

```text
У {child_name} стоит статус болезни с {date}. Нужно проверить, есть ли справка/подтверждение и финализировать отсутствие.
```

## 14.8 Условие закрытия

Задача закрывается, когда админ поставил один из финальных статусов:

```text
ABSENT_SICK_CONFIRMED
ABSENT_UNEXCUSED_FINAL
ABSENT_VACATION_APPROVED
ABSENT_EVENT
ABSENT_QUARANTINE
```

или вручную закрыл задачу с комментарием.

## 14.9 Важное правило

Справка как файл не хранится в системе.

```text
Количество активных детей в группе стало больше 15.
```

# 23. Системные расписания / cron jobs

## 23.1 Проверка табелей в 18:00

Запуск:

```text
Каждый день в 18:00
```

Действие:

```text
Найти занятия текущего дня, где Lesson.status != ATTENDANCE_COMPLETED.
Создать ATTENDANCE_NOT_FILLED задачи.
```

Важно:

```text
Не списывать занятия автоматически.
```

---

## 23.2 Проверка болезней через неделю

Запуск:

```text
Ежедневно, например утром или при открытии системы.
```

Действие:

```text
Найти AttendanceRecord со статусом ABSENT_SICK_PENDING, созданные 7+ дней назад, без финального статуса.
Создать SICKNESS_FOLLOW_UP, если ещё нет открытой задачи.
```

---

## 23.3 Проверка недопуска

Запуск:

```text
Перед занятием / при открытии занятия / ежедневная проверка.
```

Действие:

```text
Если баланс ребёнка = -1 и оплата не внесена до следующего занятия,
установить AdmissionStatus = NOT_ADMITTED.
Создать CHILD_NOT_ADMITTED задачу.
```

---

## 23.4 Проверка детей без активного абонемента

Запуск:

```text
Ежедневно или при создании/открытии занятия.
```

Действие:

```text
Найти ACTIVE детей без активного Subscription на текущий период.
Создать CHILD_WITHOUT_ACTIVE_SUBSCRIPTION задачу.
```

---

## 23.5 Проверка перегруженных групп

Запуск:

```text
При добавлении ребёнка в группу.
Также можно проверять ежедневно.
```

Действие:

```text
Если активных детей > 15, создать GROUP_OVER_CAPACITY задачу.
```

## 24. Правила дедупликации задач

Чтобы не создавать десятки одинаковых задач, система должна проверять наличие открытой задачи перед созданием новой.

## 24.1 Общий принцип

Перед созданием задачи проверить:

```text
type
related_entity_type
related_entity_id
status in (OPEN, IN_PROGRESS)
```

Если такая задача уже есть, новую не создавать.

## 24.2 Исключения

Можно создавать повторные задачи, если это разные события:

- разные занятия;
- разные даты;
- разные AttendanceRecord;
- разные MakeupCredit;
- разные TrialParticipant.

## 24.3 Примеры

### Не создавать дубликат

```text
У группы уже есть открытая GROUP_OVER_CAPACITY.
Нового ребёнка добавили, группа всё ещё > 15.
Новую задачу не создавать.
```

### Создать новую

```text
Тренер не заполнил табель по двум разным занятиям.
Создать две разные ATTENDANCE_NOT_FILLED задачи.
```

# 25. Правила автоматического закрытия задач

Некоторые задачи могут закрываться автоматически при выполнении условия.

## 25.1 ATTENDANCE_NOT_FILLED

Закрыть автоматически, когда:

```text
Lesson.status = ATTENDANCE_COMPLETED
```

## 25.2 CERTIFICATE_PENDING

Закрыть автоматически, когда:

```text
attendance.final_status != null
```

## 25.3 SICKNESS_FOLLOW_UP

Закрыть автоматически, когда:

```text
attendance.final_status установлен
```

## 25.4 MAKEUP_NEEDS_ASSIGNMENT

Закрыть автоматически, когда:

```text
MakeupCredit.status = ASSIGNED
```

## 25.5 GROUP_OVER_CAPACITY

Закрыть автоматически, когда:

```text
active children count <= 15
```

или оставить ручное закрытие — решение можно принять при реализации. Для v1 допустимо ручное закрытие.

## 25.6 TRIAL_NEEDS_PROCESSING

Закрыть автоматически, когда:

```text
TrialParticipant.status = CONVERTED_TO_ACTIVE
```

или когда админ закрыл обработку.

## 25.7 CHILD_TOOK_CREDIT_LESSON / CHILD_NOT_ADMITTED

Закрыть автоматически, когда:

```text
AdmissionStatus = ADMITTED
```

# 30. Задачи и audit log

## 30.1 Что логировать

В audit log должны попадать:

- создание CRITICAL задачи;
- закрытие CRITICAL задачи;
- ручное закрытие задачи с комментарием;
- изменение связанного статуса оплаты;
- изменение допуска;
- создание переноса;
- финализация отсутствия;
- ручная корректировка баланса.

## 30.2 Что можно не логировать

Можно не логировать каждую LOW задачу, если она не связана с деньгами, посещаемостью или детьми.

# 32. Acceptance Criteria

## 32.1 Табель не заполнен

Условие:

```text
Занятие сегодня.
В 18:00 посещаемость не заполнена.
```

Ожидаемый результат:

```text
Создана CRITICAL задача тренеру.
Создана CRITICAL задача админу.
Списаний нет.
```

---

## 32.2 Болезнь в ожидании

Условие:

```text
COACH ставит ABSENT_SICK_PENDING.
```

Ожидаемый результат:

```text
Баланс не меняется.
Создаётся CERTIFICATE_PENDING задача админу.
Через 7 дней создаётся SICKNESS_FOLLOW_UP, если статус не финализирован.
```

---

## 32.3 Болезнь подтверждена

Условие:

```text
ADMIN ставит ABSENT_SICK_CONFIRMED.
```

Ожидаемый результат:

```text
CERTIFICATE_PENDING закрывается.
SICKNESS_FOLLOW_UP закрывается или отменяется.
Создаётся MakeupCredit.
Создаётся MAKEUP_NEEDS_ASSIGNMENT задача.
```

---

## 32.4 Перенос назначен

Условие:

```text
ADMIN назначает дату переноса.
```

Ожидаемый результат:

```text
MakeupCredit.status = ASSIGNED.
MAKEUP_NEEDS_ASSIGNMENT закрывается.
```

---

## 32.5 Ребёнок взял занятие в долг

Условие:

```text
Баланс 0.
Ребёнок отмечен PRESENT.
```

Ожидаемый результат:

```text
Баланс становится -1.
AdmissionStatus = CREDIT_LESSON_USED.
Создаётся CHILD_TOOK_CREDIT_LESSON задача админу.
```

---

## 32.6 Ребёнок не допущен

Условие:

```text
Баланс -1.
Оплата не внесена.
Наступает следующее занятие.
```

Ожидаемый результат:

```text
AdmissionStatus = NOT_ADMITTED.
Создаётся CHILD_NOT_ADMITTED задача админу.
COACH видит предупреждение “Не допускать”.
COACH не может обойти блокировку.
```

---

## 32.7 Пробник после занятия

Условие:

```text
TrialParticipant был на занятии.
Занятие прошло.
```

Ожидаемый результат:

```text
Создаётся TRIAL_NEEDS_PROCESSING задача админу.
```

---

## 32.8 Группа больше 15 детей

Условие:

```text
В группе стало 16 активных детей.
```

Ожидаемый результат:

```text
Создаётся GROUP_OVER_CAPACITY задача админу.
Повторная задача не создаётся, если уже есть открытая.
```

## 32.9 Coach видит только свои задачи

Условие:

```text
COACH открывает раздел задач.
```

Ожидаемый результат:

```text
COACH видит только задачи, где он assignee или связанные с его занятием.
```

## 32.10 Admin видит операционные задачи

```text
ADMIN открывает операционный центр.
```

Ожидаемый результат:

```text
ADMIN видит CRITICAL и HIGH задачи по школе.
```

```text
заполнить табель;
проверить болезнь;
назначить перенос;
обработать пробника;
```
