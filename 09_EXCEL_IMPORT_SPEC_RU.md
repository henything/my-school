# Азбука движения — Excel Import Spec

**Проект:** Азбука движения  
**Бизнес:** Азбука движения  
**Тип документа:** Excel Import Specification / Спецификация импорта из Excel  
**Версия:** v1.0  
**Дата:** 2026-06-02  
**Язык:** русский  
**Назначение:** описать формат Excel-файла, правила импорта, валидации, маппинга данных, обработки ошибок и ограничения импорта для v1  

---

## 1. Назначение документа

Этот документ описывает спецификацию импорта данных из Excel для первой версии продукта **Азбука движения**.

Импорт нужен для стартового наполнения системы данными из текущих Excel-файлов **Азбуки движения**.

Документ предназначен для:

- владельца продукта;
- SUPER_ADMIN;
- Codex;
- backend-разработки;
- frontend-разработки;
- тестирования;
- подготовки Excel-шаблона;
- валидации данных перед импортом.

---

## 2. Контекст

На текущий момент данные школы находятся в Excel.

Известно:

- используется один Excel-файл;
- внутри файла несколько листов;
- сейчас в файле есть посещаемость по 3 филиалам;
- SUPER_ADMIN подготавливает файл перед импортом;
- в v1 не нужно импортировать историческую посещаемость;
- в v1 не нужно импортировать текущие остатки занятий;
- в v1 не нужно импортировать текущие переносы;
- в v1 не нужно импортировать финансовую историю.

Импорт в v1 нужен прежде всего для первичного заполнения справочников и операционных данных.

---

## 3. Главный принцип импорта

Excel-import в v1 — это не постоянная интеграция и не синхронизация.

Это:

```text
одноразовый или редкий инструмент первичного наполнения системы
```

Импорт должен помочь быстро перенести данные в систему, но не должен становиться основным способом ежедневной работы.

После запуска системы рабочим источником истины должна стать база Азбука движения.

---

## 4. Кто выполняет импорт

Импорт выполняет только:

```text
SUPER_ADMIN
```

В текущем проекте SUPER_ADMIN — владелец продукта/ответственный за подготовку данных.

ADMIN может видеть импортированные данные после завершения импорта.

COACH не имеет доступа к импорту.

---

## 5. Что импортируем в v1

В v1 можно импортировать:

```text
Branches / Филиалы
Coaches / Тренеры
Groups / Группы
Parents / Родители
Children / Дети
Schedule / Шаблоны расписания
Lessons / Занятия, если они заранее подготовлены
```

Опционально:

```text
Attendance source data
```

Но важно: историческую посещаемость в v1 не импортируем как историю.

Если в текущем Excel есть листы посещаемости по 3 филиалам, они могут использоваться как источник для подготовки:

- списка детей;
- списка групп;
- филиалов;
- тренеров;
- расписания.

Но не как исторический журнал посещений.

---

## 6. Что не импортируем в v1

В v1 не импортировать:

```text
Историческую посещаемость
Текущие остатки занятий
Текущие переносы
Историю оплат
Файлы справок
Файлы заявлений на отпуск
Чаты VK
Комментарии из мессенджеров
Договоры
Согласия
Полную финансовую историю
```

Также не импортировать:

- родительские аккаунты;
- пароли родителей;
- онлайн-платежи;
- данные для внешних уведомлений.

---

## 7. Рекомендуемый формат файла

Файл:

```text
.xlsx
```

Один файл с несколькими листами.

Рекомендуемое имя:

```text
azbuka_dvizheniya_initial_import.xlsx
```

Кодировка не должна быть проблемой для `.xlsx`, но текстовые поля должны быть в UTF-8 совместимом виде.

## 9. Общие правила для всех листов

## 9.1 Первая строка — заголовки

Первая строка каждого листа должна содержать названия колонок.

Пример:

```text
branch_code | branch_name | address | status
```

## 9.2 Названия колонок должны быть стабильными

Codex/backend не должен пытаться угадывать произвольные названия колонок.

Нужно использовать фиксированные технические названия:

```text
branch_code
coach_code
group_code
child_code
parent_code
```

## 9.3 Порядок колонок не должен быть важен

Система должна искать колонки по названию, а не по позиции.

## 9.4 Пустые строки игнорировать

Полностью пустые строки должны пропускаться.

## 9.5 Лишние колонки игнорировать

Если в файле есть дополнительные колонки, которые система не знает, их можно игнорировать, но желательно показывать предупреждение.

## 9.6 Коды нужны для связей

Для связи сущностей между листами использовать технические коды:

```text
branch_code
coach_code
group_code
parent_code
child_code
```

Это проще и безопаснее, чем связывать по ФИО.

## 9.7 Даты

Формат дат:

```text
YYYY-MM-DD
```

Пример:

```text
2026-06-15
```

## 9.8 Время

Формат времени:

```text
HH:mm
```

Пример:

```text
18:00
```

## 9.9 Телефоны

Телефоны желательно приводить к единому формату.

Рекомендуемый формат:

```text
+79991234567
```

Но на этапе импорта можно принимать разные форматы и нормализовать.

## 9.10 Статусы

Статусы должны соответствовать enum-значениям системы.

Например:

```text
ACTIVE
INACTIVE
ARCHIVED
```

Если статус пустой, система может использовать значение по умолчанию.

# 10. Лист Branches

## 10.1 Назначение

Импорт филиалов/локаций.

Филиал — место, где проходят занятия. Обычно это детский сад.

## 10.2 Название листа

```text
Branches
```

## 10.3 Колонки

| Колонка | Обязательная | Тип | Описание | Пример |
|---|---:|---|---|---|
| branch_code | Да | string | Уникальный код филиала в Excel | BR_001 |
| branch_name | Да | string | Название филиала | Детский сад №1 |
| address | Нет | string | Адрес | ул. Ленина, 10 |
| inventory_notes | Нет | text | Заметки по инвентарю | коврики, мячи |
| comment | Нет | text | Комментарий | вход со двора |
| status | Нет | enum | ACTIVE / INACTIVE / ARCHIVED | ACTIVE |

## 10.4 Значения по умолчанию

Если `status` пустой:

```text
ACTIVE
```

## 10.5 Валидация

Ошибки:

- `branch_code` пустой;
- `branch_name` пустой;
- `branch_code` дублируется;
- `status` не входит в допустимые значения.

## 10.6 Маппинг

```text
branch_code → external_import_code / temporary import mapping
branch_name → branches.name
address → branches.address
inventory_notes → branches.inventory_notes
comment → branches.comment
status → branches.status
```

---

# 11. Лист Coaches

## 11.1 Назначение

Импорт тренеров и создание пользовательских аккаунтов тренеров.

## 11.2 Название листа

```text
Coaches
```

## 11.3 Колонки

| Колонка | Обязательная | Тип | Описание | Пример |
|---|---:|---|---|---|
| coach_code | Да | string | Уникальный код тренера | COACH_001 |
| full_name | Да | string | ФИО тренера | Иванов Иван |
| login | Да | string | Логин для входа | coach_ivanov |
| temporary_password | Нет | string | Временный пароль | temp12345 |
| phone | Нет | string | Телефон | +79991234567 |
| comment | Нет | text | Комментарий | основной тренер |
| status | Нет | enum | ACTIVE / INACTIVE / ARCHIVED | ACTIVE |

## 11.4 Значения по умолчанию

Если `status` пустой:

```text
ACTIVE
```

Если `temporary_password` пустой, система может:

```text
сгенерировать временный пароль автоматически
```

или показать ошибку — решение зависит от реализации.

Для v1 рекомендуется:

```text
если temporary_password пустой → сгенерировать пароль и показать его SUPER_ADMIN после импорта
```

## 11.5 Валидация

Ошибки:

- `coach_code` пустой;
- `full_name` пустой;
- `login` пустой;
- `login` уже используется;
- `coach_code` дублируется;
- `status` не входит в допустимые значения.

## 11.6 Маппинг

```text
full_name → users.full_name
login → users.login
temporary_password → password_hash after hashing
role → COACH
status → users.status / coach_profiles.status
phone → coach_profiles.phone
comment → coach_profiles.comment
```

## 11.7 Важное правило безопасности

Пароли не должны храниться в открытом виде в базе.

`temporary_password` нужен только для первичной генерации `password_hash`.

Parents

# 14. Лист Children

## 14.1 Назначение

Импорт детей и привязка к родителям и группам.

## 14.2 Название листа

```text
Children
```

## 14.3 Колонки

| Колонка | Обязательная | Тип | Описание | Пример |
|---|---:|---|---|---|
| child_code | Да | string | Уникальный код ребёнка | CH_001 |
| full_name | Да | string | ФИО ребёнка | Петров Миша |
| birth_date | Нет | date | Дата рождения | 2021-04-15 |
| parent_code | Нет | string | Код родителя | P_001 |
| group_code | Да | string | Код группы | GR_001 |
| medical_notes | Нет | text | Мед. ограничения | аллергия |
| coach_comment | Нет | text | Комментарий тренера | активный |
| admin_comment | Нет | text | Комментарий админа | родитель просил звонить |
| status | Нет | enum | ACTIVE / PAUSED / LEFT / TRIAL / ARCHIVED | ACTIVE |

## 14.4 Значения по умолчанию

```text
status = ACTIVE
admission_status = ADMITTED
cached_lesson_balance = 0
cached_makeup_balance = 0
```

## 14.5 Валидация

Ошибки:

- `child_code` пустой;
- `full_name` пустой;
- `group_code` не найден в Groups;
- `parent_code` указан, но не найден в Parents;
- `birth_date` имеет неверный формат;
- `status` не входит в enum;
- `child_code` дублируется.

## 14.6 Главное ограничение

Ребёнок не может быть в двух группах одновременно.

В рамках импорта:

```text
один child_code должен встречаться только один раз в Children
```

Если ребёнок встречается дважды с разными group_code — ошибка.

## 14.7 Маппинг

```text
full_name → children.full_name
birth_date → children.birth_date
parent_code → children.parent_id
group_code → children.current_group_id
medical_notes → children.medical_notes
coach_comment → children.coach_comment
admin_comment → children.admin_comment
status → children.status
```

# 15. Лист Schedule

## 15.1 Назначение

Импорт шаблонов расписания групп.

## 15.2 Название листа

```text
Schedule
```

## 15.3 Колонки

| Колонка | Обязательная | Тип | Описание | Пример |
|---|---:|---|---|---|
| schedule_code | Да | string | Уникальный код строки расписания | SCH_001 |
| group_code | Да | string | Код группы | GR_001 |
| branch_code | Нет | string | Код филиала | BR_001 |
| coach_code | Нет | string | Код тренера | COACH_001 |
| weekday | Да | int/string | День недели | MONDAY / 1 |
| start_time | Да | time | Начало | 18:00 |
| end_time | Нет | time | Конец | 18:45 |
| valid_from | Нет | date | Действует с | 2026-06-01 |
| valid_to | Нет | date | Действует до | 2026-06-30 |
| status | Нет | enum | ACTIVE / INACTIVE / ARCHIVED | ACTIVE |

## 15.4 Значения по умолчанию

Если `branch_code` пустой:

```text
использовать branch_id группы
```

Если `coach_code` пустой:

```text
использовать main_coach_id группы
```

Если `end_time` пустой:

```text
можно использовать стандартную длительность занятия
```

Стандартная длительность должна быть определена в настройках или вручную.

Для v1 можно сделать `end_time` обязательным, если не хотим добавлять настройку длительности.

## 15.5 Допустимые значения weekday

Вариант 1:

```text
1, 2, 3, 4, 5, 6, 7
```

где:

```text
1 = понедельник
7 = воскресенье
```

Вариант 2:

```text
MONDAY
TUESDAY
WEDNESDAY
THURSDAY
FRIDAY
SATURDAY
SUNDAY
```

Рекомендуется поддержать оба формата на уровне парсинга, но хранить в базе как число 1–7.

## 15.6 Валидация

Ошибки:

- `schedule_code` пустой;
- `group_code` не найден;
- `weekday` некорректен;
- `start_time` пустой;
- `end_time` раньше start_time;
- `coach_code` указан, но не найден;
- `branch_code` указан, но не найден.

## 15.7 Маппинг

```text
group_code → schedule_templates.group_id
branch_code → schedule_templates.branch_id
coach_code → schedule_templates.coach_id
weekday → schedule_templates.weekday
start_time → schedule_templates.start_time
end_time → schedule_templates.end_time
valid_from → schedule_templates.valid_from
valid_to → schedule_templates.valid_to
status → schedule_templates.status
```

# 16. Лист Lessons

## 16.1 Назначение

Опциональный импорт конкретных занятий.

В v1 предпочтительнее генерировать занятия из `Schedule`.

Но если SUPER_ADMIN заранее подготовил конкретные занятия, можно импортировать лист `Lessons`.

## 16.2 Название листа

```text
Lessons
```

## 16.3 Колонки

| Колонка | Обязательная | Тип | Описание | Пример |
|---|---:|---|---|---|
| lesson_code | Да | string | Уникальный код занятия | LES_001 |
| group_code | Да | string | Код группы | GR_001 |
| branch_code | Нет | string | Код филиала | BR_001 |
| coach_code | Нет | string | Код тренера | COACH_001 |
| lesson_date | Да | date | Дата занятия | 2026-06-15 |
| start_time | Да | time | Время начала | 18:00 |
| end_time | Нет | time | Время окончания | 18:45 |
| status | Нет | enum | SCHEDULED / CANCELLED | SCHEDULED |
| comment | Нет | text | Комментарий | пробное расписание |

## 16.4 Значения по умолчанию

```text
status = SCHEDULED
branch_code = branch группы
coach_code = main coach группы
```

## 16.5 Валидация

Ошибки:

- `lesson_code` пустой;
- `group_code` не найден;
- `lesson_date` некорректна;
- `start_time` пустой;
- дубль занятия по group_code + lesson_date + start_time;
- `status` не входит в допустимые значения.

## 16.6 Важное правило

Если используются и `Schedule`, и `Lessons`, нужно избежать дублей.

Рекомендуемый подход:

```text
В initial import либо импортировать Schedule и потом генерировать Lessons,
либо импортировать конкретные Lessons.
Не делать оба процесса без проверки дублей.
```

# 17. Лист AttendanceSource

## 17.1 Назначение

Опциональный лист для текущих Excel-листов посещаемости.

Так как историческую посещаемость в v1 не импортируем, этот лист используется только как источник для ручной подготовки данных.

## 17.2 Название листа

```text
AttendanceSource
```

## 17.3 Статус в v1

```text
Не является обязательным листом.
Не импортируется как история посещаемости.
Может использоваться SUPER_ADMIN для подготовки Children / Groups / Schedule.
```

## 17.4 Возможное использование

Если текущий Excel содержит посещаемость 3 филиалов, можно:

1. вручную привести данные к шаблонам `Children`, `Groups`, `Schedule`;
2. не импортировать старые посещения;
3. начать работу системы с нового периода.

---

# 18. Порядок импорта

Рекомендуемый порядок:

```text
1. Branches
2. Coaches
3. Groups
4. Parents
5. Children
6. Schedule
7. Lessons, если используется
```

Почему такой порядок:

- Groups зависят от Branches и Coaches;
- Children зависят от Parents и Groups;
- Schedule зависит от Groups, Branches и Coaches;
- Lessons зависят от Groups, Branches и Coaches.

# 19. Процесс импорта в UI

## 19.1 Шаг 1 — Загрузка файла

SUPER_ADMIN загружает `.xlsx`.

UI показывает:

```text
Файл загружен. Начинаем проверку.
```

## 19.2 Шаг 2 — Валидация

Система проверяет:

- наличие обязательных листов;
- наличие обязательных колонок;
- типы данных;
- ссылки между листами;
- дубли;
- enum-значения;
- формат дат и времени.

## 19.3 Шаг 3 — Preview

Перед импортом показать:

```text
Branches: 10 строк, 0 ошибок
Coaches: 8 строк, 0 ошибок
Groups: 20 строк, 1 ошибка
Children: 150 строк, 3 ошибки
Schedule: 40 строк, 0 ошибок
```

## 19.4 Шаг 4 — Ошибки

Если есть ошибки, показать таблицу:

| Лист | Строка | Поле | Ошибка |
|---|---:|---|---|
| Children | 15 | group_code | Группа GR_999 не найдена |
| Coaches | 4 | login | Логин уже используется |

## 19.5 Шаг 5 — Подтверждение

Если критичных ошибок нет, SUPER_ADMIN нажимает:

```text
Подтвердить импорт
```

## 19.6 Шаг 6 — Импорт

Система создаёт сущности в базе.

## 19.7 Шаг 7 — Результат

Показать:

```text
Импорт завершён.
Создано филиалов: N
Создано тренеров: N
Создано групп: N
Создано родителей: N
Создано детей: N
Создано шаблонов расписания: N
Создано занятий: N
Ошибок: N
```

# 20. Режимы импорта

## 20.1 Dry-run / validation only

Обязательный режим.

Система проверяет файл, но ничего не создаёт.

## 20.2 Confirmed import

Система создаёт записи только после подтверждения SUPER_ADMIN.

## 20.3 Partial import

Для v1 лучше избегать частичного импорта при критичных ошибках.

Рекомендуемое правило:

```text
Если есть критичные ошибки в обязательных листах — импорт не выполняется.
```

## 20.4 Non-critical warnings

Предупреждения не должны блокировать импорт.

Примеры предупреждений:

- пустой VK;
- пустой телефон;
- нет комментария;
- нет medical_notes;
- нет inventory_notes.

---

# 21. Типы ошибок

## 21.1 Critical errors

Блокируют импорт.

Примеры:

- нет обязательного листа;
- нет обязательной колонки;
- пустой обязательный код;
- ссылка на несуществующую сущность;
- дубль уникального кода;
- неверный enum;
- неверный формат даты;
- ребёнок указан в двух группах.

## 21.2 Warnings

Не блокируют импорт.

Примеры:

- пустой телефон родителя;
- пустой VK;
- пустой адрес филиала;
- пустой комментарий;
- нет даты рождения ребёнка;
- нет medical_notes.

# 23. Upsert vs Create-only

## 23.1 Рекомендация v1

Использовать режим:

```text
create-only
```

Это значит:

- импорт создаёт новые записи;
- существующие записи не обновляются автоматически;
- если найден дубль — ошибка или предупреждение.

Причина:

- снизить риск испортить данные;
- initial import выполняется редко;
- SUPER_ADMIN может подготовить файл вручную.

## 23.2 Будущий режим

В v2 можно добавить:

```text
upsert
```

Но в v1 это не обязательно.

# 26. Безопасность импорта

## 26.1 Доступ

Только:

```text
SUPER_ADMIN
```

## 26.2 Пароли

Если Excel содержит временные пароли тренеров:

- не сохранять пароль в открытом виде;
- сразу превращать в password_hash;
- не показывать пароль повторно после импорта;
- лучше дать SUPER_ADMIN скачать/скопировать список временных паролей сразу после генерации.

## 26.3 Файлы

В v1 можно не хранить сам Excel-файл постоянно.

Допустимо хранить только:

- имя файла;
- ImportBatch;
- ошибки;
- результаты импорта.

Если файл хранится, доступ только SUPER_ADMIN.

## 26.4 Персональные данные детей

Импорт содержит персональные данные.

Требования:

- доступ только SUPER_ADMIN;
- не показывать файл тренерам;
- не логировать персональные данные сверх необходимости;
- не отправлять данные во внешние сервисы.

# 29. Импорт расписания и генерация занятий

Есть два подхода.

## 29.1 Подход A — импорт Schedule, потом генерация Lessons

Рекомендуемый для v1.

Импортируем:

```text
Schedule
```

После этого ADMIN в UI генерирует занятия на месяц.

Плюсы:

- меньше риска дублей;
- расписание становится управляемым;
- система сама создаёт занятия.

## 29.2 Подход B — импорт конкретных Lessons

Использовать, если SUPER_ADMIN заранее подготовил список занятий.

Плюсы:

- можно быстро перенести уже готовый календарь.

Минусы:

- выше риск дублей;
- сложнее учитывать изменения расписания.

## 29.3 Рекомендация

Для v1:

```text
Основной путь: импорт Schedule → генерация Lessons в системе.
Lessons sheet оставить опциональным.
```

# 30. Работа с текущими листами посещаемости 3 филиалов

Текущий Excel содержит посещаемость по 3 филиалам.

Для v1:

```text
Не импортировать исторические посещения как AttendanceRecord.
```

Рекомендуемый процесс:

1. SUPER_ADMIN анализирует текущий Excel.
2. Извлекает актуальные филиалы.
3. Извлекает группы.
4. Извлекает детей.
5. Извлекает тренеров.
6. Извлекает расписание.
7. Переносит данные в шаблон импорта.
8. Загружает подготовленный файл.
9. Система начинает вести посещаемость с нового периода.

В Children указан group_code, которого нет в Groups.

Система показывает ошибку и не импортирует файл.

Созданы Branches, Coaches, Groups, Parents, Children, ScheduleTemplates.

# 35. Ключевой вывод

Excel Import v1 должен быть безопасным и предсказуемым.

Главные правила:

```text
1. Импорт выполняет только SUPER_ADMIN.
2. Импорт нужен для стартового наполнения.
3. Историю посещаемости не импортируем.
4. Текущие балансы не импортируем.
5. Текущие переносы не импортируем.
6. Финансовую историю не импортируем.
7. Основные сущности: филиалы, тренеры, группы, родители, дети, расписание.
8. Все связи делаются через технические коды.
9. Перед импортом обязательна валидация и preview.
10. При ошибках импорт не выполняется.
```
