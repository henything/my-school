# Сверка абонементов и счетов

Сверка проверяет активных детей в группах за текущий месяц. Если у ребёнка есть оплачиваемые занятия по истории участия и графику, но нет абонемента, она создаёт абонемент и счёт. Повторный запуск не создаёт дублей.

## Когда выполняется

- Сразу после генерации занятий на месяц или учебный год (для текущего месяца).
- Ежедневно в 02:15 по Москве через `azbuka-monthly-cycle.timer`.
- В первые три дня месяца ежедневный запуск сначала создаёт занятия по шаблонам, затем сверяет счета.
- При зачислении ребёнка текущий месяц проверяется сразу; ежедневный запуск подхватит его, если расписание появилось позже.

Перед ежедневным начислением система применяет уже одобренные справки активных детей ко всем отмеченным болезням за их периоды включительно. Это восстанавливает старые неполностью обработанные справки и поздно внесённые отметки. Повторный запуск не создаёт повторные переносы. Ушедшие и архивные дети автоматически не обрабатываются.

## Что требует проверки администратора

В разделе «Оплаты» появляется задача «Счёт требует проверки» с причиной и именем ребёнка, если отсутствует родитель, нет оплачиваемых занятий при активном участии в группе, есть отменённый/повторный счёт или число занятий в уже выставленном счёте расходится с расписанием. После устранения причины следующая сверка закрывает задачу автоматически.

Существующие счета, особенно оплаченные, сверка не меняет. Расхождение количества занятий требует ручного перерасчёта. Пробные занятия, связанные с ребёнком, исключаются из оплачиваемых.

## Контроль начислений и смена расписания

В «Балансах» и «Задачах» блок «Контроль начислений» показывает отсутствующие счета, расхождения количества и суммы, индивидуальные дни вне расписания и неразобранные болезни. Проверяются активные дети, включая детей без группы. Болезни показываются за все даты.

Ежедневный цикл назначает задачи администратору со сроком, повышает приоритет просроченных и восстанавливает вручную закрытую задачу, если причина осталась. После устранения причины задача закрывается при следующей сверке. Уведомления остаются внутри приложения.

Болезнь можно подтвердить или признать обычным платным пропуском, указав основание. Подтверждение создаёт перенос стандартным механизмом. Затем проверяются недостающие счета текущего месяца в этой группе; уже выставленные счета автоматически не переписываются. Повторное сохранение того же решения не создаёт дублей.

В «Переносах → Справки» одобрение теперь применяет весь период, даже без привязки к одному занятию. Для ранее одобренной справки доступно «Применить к занятиям»: оно сохраняет первоначальную дату/автора решения, подтверждает оставшиеся подходящие дни и проверяет недостающий счёт только этого ребёнка. Ожидание справки больше не блокирует новый счёт: до одобрения болезнь остаётся неподтверждённой и не даёт компенсации. Задача «Нужна справка» сохраняется для контакта с родителем. При позднем одобрении уже выставленный счёт не меняется; подтверждённые переносы учитываются в ближайшем новом счёте, остаток сохраняется. Отсутствие справки не превращает болезнь в платный пропуск автоматически. При ошибке сверки одобрение сохраняется, интерфейс показывает предупреждение; повторное применение безопасно.

Для смены дней группы используйте «Расписание → Изменить расписание с даты»: действие сначала показывает отмены, защищённые табели и суммы до/после, затем сохраняет согласованные изменения вместе. Оно пересчитывает безопасные неоплаченные счета, сохраняя зачёты и льготы. При уменьшении оплаченного месяца создаётся зачёт; при увеличении — задача администратору без автоматической доплаты. Начатая оплата также требует ручной проверки.

При исправлении табеля администратором укажите причину и нажмите «Проверить исправление». Предварительный расчёт ещё не сохраняет отметки: проверьте суммы и нажмите «Сохранить табель». Дождитесь сообщения «Табель сохранён». Если данные действительно изменились после расчёта, получите новый расчёт; ошибка выделяется красным и получает фокус. Если соединение прервалось, обновите страницу и проверьте сохранённые отметки перед повторной попыткой.

Подробные шаги и сценарии проверки: [инструкция](features/schedule-change-and-billing-control.md).

## Проверка работы

На сервере:

```bash
systemctl status azbuka-monthly-cycle.timer
journalctl -u azbuka-monthly-cycle.service -n 100 --no-pager
```

Для ручного запуска сверки текущего месяца можно выполнить `systemctl start azbuka-monthly-cycle.service`. Перед запуском на боевой базе проверьте задачи в «Оплатах» и ожидаемые суммы новых счетов.
