# Подписание документов F.Doc в тестовом контуре

MVP встроен в существующие пробные занятия. Тренер отмечает «Пришёл», затем нажимает «Хочет продолжать — отправить договор и согласие». Система создаёт один комплект F.Doc с двумя шаблонами. Родитель получает ссылку от F.Doc, заполняет паспортные поля и подписывает документы. Статусы видны тренеру и администратору; подписанные PDF можно скачать из карточки пробного.

MVP не создаёт родительский аккаунт, ребёнка, счёт или платёж автоматически. Эти шаги относятся к полной версии процесса.

## Подготовка шаблонов

Исходники предоставлены заказчиком отдельно: договор `dogovor_3500_Shpak (1).wps` и согласие `forma_soglasia_subekta_na_obrabotku_personalnykh_dannykh.rtf`. Образец договора содержит данные конкретного человека, поэтому перед регистрацией шаблона в F.Doc их надо удалить. В F.Doc нужны два отдельных шаблона, их ID и числовые ID полей.

Для технического теста подготовлены два коротких документа с явной пометкой «только для проверки F.Doc». Они проверяют подстановку данных и заполнение паспорта, но не заменяют присланные юридические тексты. Тестировать их следует только с вымышленными данными и тестовым номером телефона.

Обязательные поля для автоматической подстановки:

| Документ | Поле | Источник |
| --- | --- | --- |
| Договор | ФИО родителя | Карточка пробного |
| Договор | Телефон родителя | Карточка пробного |
| Договор | Имя ребёнка | Карточка пробного |
| Согласие | ФИО родителя | Карточка пробного |
| Согласие | Телефон родителя | Карточка пробного |

Паспортные данные, адрес и иные обязательные поля настраиваются в шаблонах как поля, которые заполняет сам родитель. В базу приложения паспорт не сохраняется. Привязка шаблонов и работа `documentTemplates` требуют настройки со стороны F.Doc. Для вебхука F.Doc также просит заранее сообщить им IP принимающего сервера и событие `SetStatus`.

**Проверка текста перед отправкой:** образец договора говорит о 2 или 3 занятиях в неделю. Для детей с графиком раз в неделю этот пункт следует согласовать и исправить в шаблоне. В согласии есть отдельный блок про рекламные сообщения; проверьте с ответственным за документы, как родитель должен выразить выбор. Мы не меняем эти юридические формулировки автоматически.

## Настройки тестового сервера

Секреты задаются только в `/var/www/azbuka-staging/.env`, без коммита в Git. Основные параметры:

```dotenv
FDOC_MVP_ENABLED=true
FDOC_BASE_URL=https://demo.fdoc.ru
FDOC_API_KEY=
FDOC_CORP_ID=
FDOC_TECH_LOGIN=
FDOC_TECH_PASSWORD=
FDOC_EMPLOYEE_ID=
FDOC_APP_CODE=API
FDOC_CONTRACT_TEMPLATE_ID=
FDOC_CONSENT_TEMPLATE_ID=
FDOC_CONTRACT_PARENT_NAME_PARAM_ID=
FDOC_CONTRACT_PARENT_PHONE_PARAM_ID=
FDOC_CONTRACT_CHILD_NAME_PARAM_ID=
FDOC_CONSENT_PARENT_NAME_PARAM_ID=
FDOC_CONSENT_PARENT_PHONE_PARAM_ID=
FDOC_WEBHOOK_TOKEN=
```

`FDOC_WEBHOOK_TOKEN` — случайная строка длиной от 32 символов. Адрес вебхука для подписки `SetStatus`: `https://test.195.133.56.68.sslip.io/api/integrations/fdoc/<FDOC_WEBHOOK_TOKEN>`. F.Doc не присылает заголовок авторизации вебхука, поэтому токен находится в адресе; сервер затем сверяет статус непосредственно через F.Doc и не доверяет переданному статусу. Для подписки нужен доступ F.Doc и их настройка IP. До подписки статус можно обновить кнопкой «Проверить статус».

Чтобы внести основные доступы без отправки их в чат, откройте консоль VDSina и выполните `bash /var/www/azbuka-staging/scripts/configure-fdoc-staging.sh`. Скрипт запросит API key, corpId, логин и пароль технической учётной записи, ID сотрудника и код приложения `app` (по умолчанию `API`; если F.Doc выдал другой код, укажите его). Ключ и пароль при вводе не отображаются. Отправка документов останется выключенной, пока не настроены и не проверены шаблоны. После ввода доступов список шаблонов и ID полей можно получить командой:

```bash
cd /var/www/azbuka-staging
sudo -u azbukastage env HOME=/var/www/azbuka-staging PATH=/opt/node-v24/bin:/usr/local/bin:/usr/bin:/bin pnpm exec tsx scripts/fdoc-list-test-templates.ts
```

Подписанные PDF сохраняются на сервере в `.local/fdoc-signed` с ограниченными правами; доступ к скачиванию есть только у администраторов школы. Тренер видит статусы без паспортных данных. Для хранения вне каталога приложения можно задать `FDOC_SIGNED_FILES_DIR` с приватным каталогом и включить его в резервное копирование.

## Проверка

1. В тестовом контуре создать пробное занятие с вымышленными данными и доступным для теста телефоном.
2. Отметить, что ребёнок пришёл. Нажать «Хочет продолжать — отправить договор и согласие» один раз.
3. Убедиться, что родителю пришла ссылка, в обоих документах подставлены имена и телефон, а паспорт заполняется родителем.
4. Подписать оба документа, проверить два статуса и скачать оба PDF.
5. Повторить нажатие или получение вебхука: повторный комплект и повторное сообщение не должны создаться.

Если отправка завершилась ошибкой до получения ID документов, запись останется в состоянии `ERROR` для проверки администратором. Автоматическая повторная отправка намеренно не включена: сетевой сбой может произойти после фактической отправки F.Doc, и новый запрос рискует отправить родителю дубликат.
