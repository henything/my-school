# Перенос подписания F.Doc на рабочий контур

Пилотная группа: **81 сад (корпус 2)** (`c75009cb-8d22-4de1-b165-33db48ce7b11`). На 25 октября 2026 года в ней 8 активных детей при лимите 15; расписание есть до декабря. Перед открытием записи ещё раз проверить актуальные места и даты.

## 1. Код без публичной записи

Слить ветку с актуальным `main`, выполнить `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`. Развернуть через `scripts/deploy-prod.sh`: скрипт делает резервную копию БД, применяет миграции и запускает таймеры сверки F.Doc и копирования подписанных PDF. **Seed на проде не запускается.**

Пока `FDOC_PROD_ENABLED` и `FDOC_PUBLIC_BOOKING_ENABLED` не включены, `/join` возвращает 404 и отправка документов недоступна. `/test-journey` остаётся только на тестовом домене, а имитация оплаты не вызывается из продового пути.

## 2. Рабочий F.Doc

В консоли VDSina от root выполнить:

```bash
bash /var/www/azbuka-dvizheniya/scripts/configure-fdoc-production.sh
```

Скрипт запрашивает рабочий адрес API, ключ, corpId, код приложения, техническую учётную запись сотрудника, ID сотрудника-подписанта, ID утверждённых шаблонов договора и согласия и ID полей подстановки. Секреты в чате не передавать. До записи в `.env` скрипт проверяет получение токена F.Doc. Он включает интеграцию, но **оставляет публичную запись выключенной**.

После настройки проверить, что рабочие шаблоны содержат согласованные график и цену, поля ФИО родителя, ребёнка, телефона, даты рождения, паспортные поля для заполнения внутри F.Doc, а также подпись организации. Рабочая конфигурация не должна указывать на `demo.fdoc.ru` или тестовые шаблоны.

Перед публикацией ссылки выполнить `bash /var/www/azbuka-dvizheniya/scripts/install-join-rate-limit.sh`: Nginx ограничит частоту регистрации и записи по IP, не затрагивая остальные страницы. Скрипт сохраняет исходную конфигурацию и проверяет `nginx -t` до перезагрузки.

Статусы документов сверяются каждые 15 минут даже при пропущенном вебхуке. Для мгновенного обновления у F.Doc дополнительно зарегистрировать событие `SetStatus` на адрес `/api/integrations/fdoc/<FDOC_WEBHOOK_TOKEN>`; токен остаётся только на сервере и у F.Doc.

## 3. Проверка до открытия группы

- Проверить `/join` → 404, `/login` → 200, действующие родительские кабинеты и табели работают.
- Проверить, что `/var/lib/azbuka-dvizheniya/fdoc-signed` доступен только пользователю приложения и что `azbuka-fdoc-backup.timer` активен.
- Проверить получение подписанных рабочих PDF в контролируемой заявке. Паспортные поля в собственной БД приложения не хранятся.
- Провести реальную оплату через ЮKassa по контролируемому счёту: возврат браузера сам по себе не активирует ребёнка; подтверждённый серверный платёж активирует ровно одного ребёнка.
- Повторить вебхуки F.Doc и ЮKassa, проверить отсутствие второго комплекта, второго счёта и повторного зачёта.
- Восстановить хотя бы один подписанный PDF из резервной копии в отдельный временный каталог и сверить его с оригиналом.

## 4. Пилот

Только после проверки включить `FDOC_PUBLIC_BOOKING_ENABLED=true` в рабочем `.env` и перезапустить приложение. Опубликовать `https://azbukadvizheniya.ru/join` для одной пилотной группы. Другие группы не показываются.

Проверить первый полный путь: саморегистрация, карточки, пробное в табеле, контакт и решение тренера, выбор графика, договор и согласие, счёт с платными датами после 48-часового срока, оплата, активное членство и будущие табели. При подписании другим способом администратор загружает два PDF и фиксирует основание проверки; способ хранится отдельно от F.Doc.

Если нужно немедленно остановить новые записи, установить `FDOC_PUBLIC_BOOKING_ENABLED=false` и перезапустить приложение. `FDOC_PROD_ENABLED` оставить включённым, пока есть незавершённые подписи или оплаты: сверка должна обработать их до конца.

## 5. Наблюдение

Таймер `azbuka-fdoc-reconcile.timer` проверяет подписи, выставление счёта и активацию оплаченных детей. Ошибки в `journalctl -u azbuka-fdoc-reconcile.service` требуют ручной проверки администратором. Полная группа после позднего платежа допускает зачисление сверх лимита и создаёт задачу о превышении. Занятия, прошедшие до поздней оплаты, оформляются зачётом на следующий месяц.
